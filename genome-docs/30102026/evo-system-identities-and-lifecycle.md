## 1. Universal Identity Mapping

| Identity Key | Scope | Generator / Source | Authoritative State Owner |
| :--- | :--- | :--- | :--- |
| `sessionId` | Universal correlation key across sessions, logs, and HTTP tasks | UUID generated by `SessionManager` / `ChatSession` | `SessionManager` & `SessionRepository` |
| `taskId` | Unique identifier for individual task execution units | Generated by `TaskRequest` / `OrchestratorServiceImpl` | `Orchestrator` & `Task` model |
| `variantId` | Identifies competing trajectory mutation candidates | Generated by `ADarwinEngine` (`exp/<goal>/<id>`) | `EvolutionTree` & `TrajectoryMemory` |
| `runId` | Unique Self-Development workflow execution run ID | Generated by `SelfDevOrchestrator` (`run_<timestamp>`) | `SelfDevSupervisor` |
| `userId` | Authenticated principal identity | `UserRepository` (SQLite) | `AuthorizationService` |

---

## 2. Cross-Component State Transitions & Lifecycle Invariants

1. **Darwin Execution**: Transitions through `INIT` -> `ANALYZING` -> `EXECUTING` -> `VERIFYING` -> `WAITING_FOR_USER_DECISION` -> `DONE` / `FAILED`.
2. **Self-Development Loop**: Transitions through 18 sequential tasks managed by `SelfDevOrchestrator`.
3. **Server Operation**: Transitions through `CREATED` -> `ACCEPTED` -> `RUNNING` -> `COMPLETED` / `FAILED`.
4. **Lifecycle Invariant**: Disposing or navigating away from UI pages does not interrupt or terminate background Darwin, Self-Dev, or Server executions.
