🧬 EVO — Help

AI Evolution platform help (Family UX Standard v1.0) — served by the primary EVO HTTP server.

Overview

EVO is the Darwin platform: an Eclipse RCP workbench for autonomous, iterative AI-driven software evolution, with a web portal (Intelligence Portal), forge training lab, REST/HTTP services and a headless CLI. This page is opened from the Help menu, the F1 context-help key or directly at http://127.0.0.1:28080/help.html.

Getting Started

Workspace setup

  • Launch evo and choose (or auto-select) an Eclipse workspace. Project and configuration data is stored in the workspace; runtime state (logs, self-dev runs) lives under ~/.evo and the repository folder.
  • Use Evolution > Setup LLM / Setup Ollama to connect a local or remote model provider before running orchestration tasks.
  • Create a new AI session with Ctrl+N (M1+N) or Evolution > New AI Session.

Servers

The workbench auto-starts the platform servers on startup. Default ports (configurable via the port allocation manager):

ServicePortPurpose
Primary HTTP / REST28080Main web portal, REST API, help
Secondary HTTP / Portal28180Intelligence Portal (dashboard)
MCP Server28280Model Context Protocol
Develop Agent28380Autonomous coding agent
Supervisor REST API28480Supervisor HTTP API
Supervisor Control (TCP)28580Supervisor control channel (not a web surface)

Tools > Open Web Interface opens the portal in your system browser on the actual bound port.

Context Help

Navigator / Project Explorer

The EVO Navigator shows the workspace projects, orchestrations, models and resources. Right-click a file or folder for the EVO platform context menu — including Copy Path and Open Terminal for filesystem selections, plus forge session actions, AI assistance and quick navigation.

Editor (Multi-page) — Tools page

The multi-page editor hosts the AI Chat, Task Stack, Architecture, Development, Properties, Tests, Peer Review and Tools pages. The Tools page provides an embedded terminal group driven by the ShellTool engine. For safety the shell tool only permits a fixed command whitelist:

mvn mvn.cmd git ls pwd cd mkdir echo ollama gcc g++ make cmake java javac curl sh bash

Note: the embedded terminal is command-whitelisted; for an unrestricted system shell use Tools > Open Terminal (or the context-menu Open Terminal), which opens a real terminal emulator in the workspace/project directory.

Properties

The Properties view shows the selection's model/project properties (EMF-based). Memory and orchestration context are shown in the Memory/Context page of the multi-page editor and in Evolution > Memory Context.

Memory / Context

EVO keeps the active orchestration context and conversation state per session. The Memory Context view/page exposes the current context snapshot; sessions are reconciled on restart.

CLI Commands (Headless)

The headless product (eu.kalafatic.evolution.controller.application.HeadlessApplication, product "Evolution Headless") provides a small interactive CLI. Slash is optional, commands are lowercase. Example: evo -application eu.kalafatic.evolution.controller.application.HeadlessApplication /status. With a TTY and no command arguments it starts an evo> REPL (exit with /exit or Ctrl+D).

CommandDescription
/help [topic]Show command help (optionally per topic)
/statusServer status via GET /server/status (ServerManager state fallback)
/webPrint the web interface URL
/terminalOpen a system terminal in the workspace directory
/logs showTail the EVO log file (evo.log)
/sessionsList forge sessions (GET /forge/sessions)
/modelsList EVO models (local Ollama models + provider defaults)
/providersList LLM providers and connected coding harness providers
/agentsList connected coding agents (harness adapters)
/configShow the authoritative EVO port/service configuration
/stopGracefully stop all EVO servers
/startStart the primary EVO HTTP server
/restartRestart the primary EVO HTTP server
/exitExit the interactive CLI (REPL only)

Note: /models, /providers and /agents are generated from live capability data (Ollama models, the AiProviders configuration and the ConnectedApplicationRegistry) — there is no unrelated static list.

Diagnostics

  • Server status: GET http://127.0.0.1:28080/server/status — live server state (also available in the portal under System Analytics).
  • Contextual actions: GET /api/contextual/actions?type=&id= and POST /api/contextual/execute — the Darwin family contextual action contract.
  • Supervisor UI: supervisor REST API on 28480, supervisor control TCP on 28580 (open from the Development page "Open Control Hub" button).
  • Logs: EVO writes evo.log in the Eclipse state location logs directory — inspect with /logs show in the headless CLI.
  • OSGi state: GET /server/osgi — bundle/service overview.

Ports shown are the platform defaults (+20000 series); the actual bound ports may differ when re-allocated. Use /config or the Server page for the live values.
